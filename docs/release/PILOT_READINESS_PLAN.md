# PILOT READINESS PLAN — مِداد

## المرحلة الحالية

المنتج **PILOT CANDIDATE** وليس Pilot Ready. البنية التقنية والرحلات المحدودة مثبتة آليًا، لكن الحكم البشري غير متوفر. الخطوة التالية ليست إضافة محرك جديد؛ بل تشغيل جلسات ملاحظة منضبطة.

## خطة التنفيذ

يُختار ثلاثة معلمين وخمسة طلاب من الفئة المستهدفة، وتُنفذ الجلسات على بيانات تدريبية فقط. يبدأ كل معلم بمهمة إنشاء درس عربي ثم مهمة رياضيات، ويتبع كل طالب نشاطًا جاهزًا. يسجل المراقب الفهم والاستقلالية وطلبات المساعدة والأخطاء ووضوح الرسائل، ثم يحلل كل فئة منفصلة.

قبل كل جلسة، تُنظف بيانات المتصفح وتُحفظ نسخة احتياطية من ملف الاختبار. بعد كل جلسة، تُراجع سلامة الدرس والتصدير والاستعادة، وتُحذف أي تسجيلات أو ملاحظات تعريفية غير لازمة. لا يجوز تغيير السيناريو لإخفاء مشكلة، ولا إدخال بيانات صف حقيقية.

## بوابة النجاح

لا يُعلن `PILOT READY` إلا إذا اكتملت الرحلة الأساسية للمعلم والطالب دون blocker، وفهم المشاركون التعليمات والنتيجة والخطوة التالية، وبقي المحتوى سليمًا بعد الحفظ والاستعادة والنقل. تُسجل الجلسة الصعبة كما هي؛ لا تُحوّل النتيجة إلى متوسط واحد يخفي الفروق.

## إذا فشلت خطوة

إذا تعذر إنشاء النشاط أو فُقد محتوى أو ظهر تفسير مضلل، تتوقف الجلسة ويُصنف الأمر blocker. إذا كان التردد محدودًا، تُسجل الملاحظة كـYELLOW ويُقرر لاحقًا إن كان copy-only fix كافيًا. لا تُضاف Authentication أو Cloud Sync أو AI أو OCR لمعالجة فجوة usability في هذه المرحلة.

## مخرجات الجلسات

تُملأ `HUMAN_PILOT_RESULTS.md` فقط بعد حدوث الجلسات فعلًا، وتُحدّث `PILOT_READINESS.md` و`MVP_FINAL_READINESS.md` بالأدلة البشرية المنفصلة عن Playwright وVitest. عند غياب المشاركين يبقى الحكم `NOT VERIFIED`.
