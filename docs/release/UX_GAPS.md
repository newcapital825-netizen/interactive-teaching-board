# UX GAPS — مِداد

## الفجوات التي عولجت

تمت إزالة معظم التسربات التقنية من الواجهة المرئية، وتعريب عناوين مسار التعلم، وتوضيح الفرق بين نتيجة التقييم وقرار المعلم، وتحسين رسائل الحفظ المحلي، والاستيراد، والاستعادة، والحالات غير المدعومة. لم تتغير البيانات أو العقود الداخلية.

## الفجوات المتبقية

| الأولوية | الفجوة | التصنيف | الأثر |
|---|---|---|---|
| P0 | لا توجد ملاحظة من معلمين وطلاب حقيقيين | NOT VERIFIED | يمنع إعلان Pilot Ready |
| P1 | لا توجد حسابات أو عزل مستخدمين متعددين | KNOWN LIMITATION | يمنع استخدام صف حقيقي أو بيانات شخصية |
| P1 | بعض المسارات تعرض حدود الشريحة بدل تغطية عامة | INTENTIONAL BOUNDARY | يجب ألا يُفهم المنتج كمحرك عام |
| P1 | Touch وStylus وScreen Reader غير متحققة | NOT VERIFIED | يحتاج تحققًا على أجهزة فعلية |
| P2 | حالة فارغة للطالب عند عدم تجهيز نشاط تحتاج تحققًا بشريًا | PARTIALLY PROVEN | قد تحتاج صياغة أو CTA إضافية بعد الملاحظة |
| P2 | بعض عمليات export/import تعتمد على file picker/browser behavior | PARTIALLY PROVEN | يلزم smoke فعلي في بيئة Pilot |
| P2 | لا يوجد performance budget رسمي | NOT VERIFIED | لا يجوز إعلان release performance guarantee |

## قاعدة القرار

لا تُعالج الفجوات بإضافة ميزات عشوائية. إذا أثبتت جلسات Pilot أن خطوة أساسية غير مفهومة، يُنفذ إصلاح صغير قابل للعزل ويعاد تشغيل الاختبار الآلي؛ أما الفجوات المقصودة مثل غياب Cloud Sync فتظل خارج النطاق.
